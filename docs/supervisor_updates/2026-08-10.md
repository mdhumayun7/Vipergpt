# Supervisor update — 2026-08-10

This week established the full reproduction scaffold and a working (unverified)
implementation of the ViperGPT pipeline targeting all four benchmark tables
(RefCOCO/RefCOCO+, GQA, OK-VQA, NExT-QA). After reading the paper and the official
Columbia code, I confirmed the central constraint driving the project: the paper's
program generator, OpenAI Codex `code-davinci-002`, was deprecated in March 2023,
so an exact reproduction is impossible. The official repository itself ships a
CodeLlama backend as a substitute, which validates the plan to use an open-weights
code model; I have committed to Qwen2.5-Coder-7B-Instruct as the generator and
Llama-3.1-8B-Instruct for the external-knowledge and multiple-choice text queries
that the paper served with GPT-3. Both substitutions are logged as formal deviations
and are the most likely source of any accuracy gap, so a code-model size ablation is
planned to quantify that effect.

The method spec and implementation plan are written and were signed off. On the
implementation side I have the program executor, the ImagePatch/VideoSegment API
surface, the module dispatch bus (with CPU mock backends for testing), wrappers for
GLIP, X-VLM, BLIP-2, MiDaS and the text LLM, the four dataset loaders ported from the
official code, and evaluators that mirror the official metrics — including the
RefCOCO subtlety that the reported figure is mean IoU (not accuracy) computed in a
bottom-left coordinate convention, which is a known bug trap I have documented.

The main blocker is environmental: the development shell in this session never came
online, so I could not run the unit/smoke tests or make the git commits, and the
actual reproduction runs require the GPU cluster with weights and datasets
downloaded. Nothing about the code depends on that shell — the immediate next steps
are to run `make test` from a clean clone to confirm the mock path, build the GLIP
fork on a login node (the highest integration risk), and then launch the four
reproduction jobs starting with RefCOCO, which needs the fewest modules. I expect
first real numbers on Table 1 next.
